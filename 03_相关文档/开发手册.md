# 开发手册：实现约定与维护边界

课程交付项：5.2.3相关文档。本手册解释现有实现如何组织、为何采用这些数据约定，以及修改后应如何复核。准确的函数签名和示例另见 [接口文档](接口文档.md)。

## 1. 代码职责与数据流

本项目采用算法、GUI和实验数据校验三个模块。算法不导入Tkinter，窗口不自行实现S盒或轮运算，便于脚本测试和复用。

| 文件 | 职责 | 依赖方向 |
|---|---|---|
| saes.py | 参数校验、轮变换、编码、多重、MITM、CBC | 标准库 functools、secrets |
| main.py | 输入、任务状态和结果展示 | 导入saes、experiment_io；Tkinter、线程、队列 |
| experiment_io.py | JSON结构、向量校验、攻击文本解析 | 导入saes；json、dataclasses |
| tests/test_saes.py、test_experiment_io.py | 已知答案、完整状态空间、轨迹和导入契约 | 算法与数据校验模块；unittest |
| verify.py | 执行测试、输出摘要和示例 | 读取tests，调用saes，写结果文件 |

```text
用户填写字段
  → main.py 校验/转换二进制或HEX
  → saes.py 的整数/字节接口
  → GUI格式化展示

MITM：后台线程 → queue.Queue → 主线程 after 回调 → 进度与候选
verify.py → unittest → test_log.txt + 自动测试摘要.md + examples/
```

目录顺序仍为01源代码、02测试结果、03相关文档。人工图文报告与自动摘要分开：verify.py不会覆盖截图和逐关实验记录。

## 2. 数据进入算法前的约定

每个分组和子密钥是0…65535的整数。GUI二进制文本由parse_bits转换；密文HEX由bytes.fromhex转换。基础分组、CBC与多重加密接口不会根据内容自动猜测编码或填充。

将16位分成n0、n1、n2、n3四个半字节后，状态按列摆放：

```text
输入：n0 || n1 || n2 || n3
状态： [ n0  n2 ]
       [ n1  n3 ]
```

ShiftRow交换第二行n1和n3，执行两次恢复原状态。字节与分组之间使用大端序，例如字节12 34组成整数0x1234。此约定直接影响跨实现测试。

## 3. 轮运算与密钥生成

| 参数 | 当前值 |
|---|---|
| 分组／主密钥位数 | 16／16 |
| S盒 | 9 4 A B D 1 8 5 6 2 0 3 C E F 7 |
| 逆S盒 | 由S盒置换求逆生成 |
| GF模多项式 | x^4+x+1，即0x13 |
| 列混淆矩阵 | [[1,4],[4,1]] |
| 逆列混淆矩阵 | [[9,2],[2,9]] |
| 两个轮常数 | 0x80、0x30 |

GF乘法按位累加，溢出四位时使用0x13约减。半字节替代由S盒查表完成，轮密钥加使用逐位XOR。

### 3.1 六个字节如何组成三把轮密钥

主密钥高低字节为w0、w1。g函数先交换字节内两个半字节，再做S盒替代并XOR轮常数。

```text
w2 = w0 XOR g(w1, 0x80)
w3 = w2 XOR w1
w4 = w2 XOR g(w3, 0x30)
w5 = w4 XOR w3
K0 = w0 || w1
K1 = w2 || w3
K2 = w4 || w5
```

本次4AF5生成4AF5、DD28、87AF；教材示例2D55生成2D55、BCE9、A34A。expand_key使用最多65536项的LRU缓存，减少重复分组与攻击中的扩展开销。

### 3.2 加密与逆序还原

```text
P XOR K0
 → SubNib → ShiftRow → MixColumn → XOR K1
 → SubNib → ShiftRow → XOR K2
 = C
```

最后一轮没有列混淆。解密从XOR K2开始，逆行移位、逆替代，然后XOR K1、逆列混淆，再逆行移位、逆替代、XOR K0。
encryption_trace和decryption_trace分别返回正向与逆向步骤标签及整数状态，GUI据此显示二进制和HEX，不在窗口层重复计算另一套轨迹。

## 4. 字符消息与多重加密

ASCII接口严格编码，两个字节一组，采用块大小2字节的PKCS#7。奇数字节补01，偶数字节及空串补02 02。解密先检查并移除填充，再解码ASCII。密文Latin-1映射只用于展示，HEX才是本界面接受的文本密文输入。
这一封装约定独立于单分组S-AES；与别的实现互测文本时还需要约定填充。

设E、D为单次S-AES，密钥在合并输入中按K1||K2||K3排列：

| 模式 | 加密过程 | 解密顺序 |
|---|---|---|
| 双重32位 | E_K2(E_K1(P)) | K2→K1 |
| 三重32位EEE | E_K1(E_K2(E_K1(P))) | K1→K2→K1 |
| 三重48位EEE | E_K3(E_K2(E_K1(P))) | K3→K2→K1 |

当前程序没有实现EDE三重约定。跨组比较三重结果时必须先统一方案；本次图形界面证据采用32位EEE。

## 5. MITM：候选的完整性与界面响应

对第一对P、C，先枚举所有K1，将E_K1(P)映射到K1列表；再枚举所有K2，计算D_K2(C)并查表。中间值相同只产生候选，还要满足其他已知明密文对才能保留。
映射值必须是列表，若仅保存最后一个K1，会在碰撞时丢失可能的真实密钥。tests中单对搜索验证碰撞候选保留，再以额外两对过滤并对照完整攻击结果。

建表与扫描分别是2^16次单密钥枚举，表空间O(2^16)；额外过滤成本与命中数及数据对数量有关。单对16位数据通常无法唯一确定32位密钥对。

GUI启动daemon后台线程，工作线程只发送队列事件。主线程用after每100毫秒读取事件并更新控件；算法每1024个扫描项回调进度并检查取消。输入错误在启动前提示，取消通过threading.Event传入算法，关闭窗口时也设置取消信号。
算法返回全部候选；GUI最多显示100对，JSON导出保留全部结果。进度条代表两次密钥扫描，不精确代表候选过滤耗时。

## 6. CBC与基准比较

C0=IV；Ci=E_K(Pi XOR C(i-1))；Pi=D_K(Ci) XOR C(i-1)。接口接收完整整数分组，无填充。random_iv调用secrets.randbits(16)，IV需供解密方使用。
GUI在加密时保留原分组、密钥、IV作为基准。解密本身只需密文、密钥和IV；当密钥与IV和基准一致时，才显示原文差分。

“翻转C1最低位”对第一块密文XOR 1，再解密显示差异。修改Ci会扰乱Pi，并在P(i+1)产生相同XOR差分；更后的分组不继续受影响。改变IV只影响首块。
输入框与模式变化通过StringVar监听及控件事件撤下旧输出，提示重算；结果区只读。攻击期间锁定输入，完成或取消后恢复。归档的早期截图中有一张修改IV但未重算的画面，仍在补充记录中保留并注明局限。

## 7. 错误边界与维护验证

word验证16位整数，parse_bits验证指定长度与字符；字符串解密检查字节对齐、填充和ASCII解码。无效参数主要抛ValueError，GUI转换为提示框；取消攻击抛InterruptedError，后台异常通过队列显示。
S盒、GF及状态变换辅助函数供内部使用，不是自动识别格式的通用密码API。接口的具体类型与文件格式见 [接口文档](接口文档.md)。

| 改动位置 | 至少应复核 |
|---|---|
| S盒／GF／状态排列／密钥扩展 | 公开已知答案、逆变换及完整明文空间 |
| ASCII编码或填充 | 空串、奇偶长度、控制字符与无效填充 |
| 多重密钥顺序 | 双重及32/48位三重的加密定义和逆序 |
| MITM映射、过滤或取消 | 碰撞保留、真实密钥、单对/多对一致性和取消 |
| CBC链式处理 | 正常恢复、密文单比特和IV单比特差分 |
| 目录或文档引用 | 启动脚本、输出路径、Markdown图片与链接 |

根目录双击“运行测试.bat”，或运行 `python .\01_源代码\verify.py`。原始日志、自动摘要和手动截图分别保留各自运行来源；重新生成日志后，耗时以最新输出为准。
目前20项自动验证及用户上传截图已整理；真实组间验证仍需对方独立程序的证据，不能由本机自测替代。
