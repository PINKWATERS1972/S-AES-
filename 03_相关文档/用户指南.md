# 用户指南：从输入到保存实验记录

本指南对应当前 Tkinter 桌面程序。基础数据为16位二进制，文本页接受 ASCII；CBC 页处理完整的16位分组。已经保存的运行图位于 [测试结果目录](../02_测试结果/五关测试结果.md)，可一边操作一边核对。

## 1. 启动、输入与输出

打开 `D:\信息安全导论\S-AES作业`，双击根目录的“启动程序.bat”。脚本优先使用本机 `D:\anaconda3\python.exe`，其他电脑可使用带 Tkinter 的 Python 3.10+。不需要安装 PyQt 或其他第三方包。

如使用终端，在项目根目录执行：

```powershell
python .\01_源代码\main.py
```

不要只复制 main.py，运行时同目录还需要 saes.py 和 experiment_io.py。不要在未解压的压缩包内直接启动。

| 输入位置 | 接受的内容 | 注意点 |
|---|---|---|
| 基础数据、密钥、IV | 固定位数的 0 和 1 | 保留前导零；不要输入 HEX 字母 |
| 多重加密密钥 | 合并的32或48位二进制 | 顺序为 K1||K2 或 K1||K2||K3 |
| ASCII 明文 | ASCII 字符串 | 中文、表情不在本页范围内 |
| ASCII 密文 | 十六进制字节 | 每字节两位 HEX，可含空白 |
| 攻击输入 | 每行一对二进制 P C | 每个字段16位，字段内部不加空格 |
| CBC 分组 | 用空格分开的16位二进制块 | 不自动对任意长度数据填充 |

程序不会自动保存所有界面输出。修改输入字段或模式后，会撤下旧结果并显示“原结果已失效”的提示，重新点击操作按钮即可计算。

## 2. 第一关：检查一次加密和还原

进入“1 基础测试”，填写明文 `1101011100101000` 和密钥 `0100101011110101`。点击“加密并显示过程”，结果应为 `0010010011101100`（24EC）。输出同时列出轮密钥及各轮状态；解密也会列出逆变换过程。
把密文复制回“明文／密文”框，密钥保持不变，点击“解密”，结果应恢复为 `1101011100101000`（D728）。

通过条件不仅是“有输出”，还应核对公开已知密文24EC，以及恢复的明文是否逐位一致。

![基础加密与过程](../02_测试结果/第1关_基础加解密/01_基础加密.png)

完整的加密、解密和状态值见 [第一关记录](../02_测试结果/第1关_基础加解密/实验记录.md)。

## 3. 第二关：把测试数据交给其他实现

进入“2 交叉测试”，填写双方约定的16位密钥。点击“导出给其他小组”，保存 JSON 并交给对方；对方要用自己独立编写的程序计算加密结果、解密结果，再返回实际值和截图。
收到同格式 JSON 后，点击“导入并验证”；如果对方只提供密文，则在基础页输入其密文和共同密钥，点击解密并比较原文。

文件导入验证显示“通过”，仅表示文件里的数据与本程序吻合。完成课程的组间测试，还要有对方程序的实际运行记录。当前记录页已经说明这一点，待双方测试后填写 [交叉测试记录](../02_测试结果/组间交叉测试记录.md)。

双方结果不一致时，先统一状态排列、S盒、轮常数、列混淆、字节顺序和是否填充。基础单分组测试不填充。JSON 格式见 [接口文档](接口文档.md)。

## 4. 第三关：从 ASCII 到可传输密文

1. 在“3 ASCII 扩展”中输入 `Hello S-AES!`，密钥用默认16位值。
2. 点击“加密字符串”，程序自动把 HEX 密文填入下方框，输出为 `0757F12B3AC522790247E274D35D`。
3. 保留密钥和下方 HEX，点击“解密字符串”，应恢复 `Hello S-AES!`。上方明文框不参与解密，不需要替换。

本页每两字节分组，采用2字节块大小的 PKCS#7 填充；空字符串、奇数或偶数字节长度均可往返。密文可能含不可打印字节，使用 HEX 复制可避免乱码损失。界面里的 Latin-1 映射和控制字符转义用于观察，不是另一种待输入的格式。

## 5. 第四关：双重、三重和中间相遇

### 5.1 双重加密与三重加密

进入“4 多重加密”，从下拉框选择模式，再输入数据和对应长度的合并密钥。加密完成后，将结果的16位二进制密文复制回数据框，以相同模式和密钥点击解密。

| 方案 | 实际使用的子密钥顺序 | 密钥输入位数 |
|---|---|---|
| 双重 EE | K1→K2 | 32 |
| 三重 EEE／32位 | K1→K2→K1 | 32 |
| 三重 EEE／48位 | K1→K2→K3 | 48 |

本次截图的双重用例是 D728→657D→D728；三重32位用例是12FA→8483→12FA，两者均使用 K1=4AF5、K2=DD28。三重用例与双重用例的原文不同，比较时以各自原文为准。

32位合并密钥示例：

```text
01001010111101011101110100101000
```

48位合并密钥示例（K3=1234）：

```text
010010101111010111011101001010000001001000110100
```

课程三重加密要求两种方案任选一种，本次界面证据采用32位。只展开菜单或改变选项而未重新计算，不算新模式的运行结果。

### 5.2 中间相遇攻击

进入“4 中间相遇”，点击“填入演示数据”后再点“开始完整搜索”。无需输入真实密钥，搜索只使用三组已知明密文对。等待后应得到唯一候选4AF5／DD28；已保存的用户截图耗时1.805秒，其他运行速度会不同。
搜索期间输入、填入示例及重复启动按钮会锁定，可使用取消按钮；完成后恢复编辑并可导出全部候选。界面最多显示前100对，导出不截断候选。

若有多个候选，增加来自同一组双密钥的独立明密文对；若没有候选，检查输入是否确实来自双重加密、每项位数是否正确、密钥是否在不同数据对之间保持一致。

![攻击完成后的候选](../02_测试结果/第4关_多重与密钥恢复/06_中间相遇搜索结果.png)

## 6. 第五关：先还原，再观察篡改

为复现已保存的实验，填入密钥4AF5、IV=1234和三块明文1234、5678、9ABC的二进制形式：

```text
密钥：0100101011110101
IV：  0001001000110100
明文：0001001000110100 0101011001111000 1001101010111100
```

1. 点击“CBC 加密”，密文三块为52B1、9936、F9DC。
2. 点击“解密／对比”，三块明文恢复，XOR差分全部为0000。
3. 点击一次“翻转 C1 最低位并对比”，P1变为6231，P2变为5679，P3仍为9ABC。
4. 保存篡改结果，再次点击同一按钮会恢复该位；需要新基准时重新点击加密。

![CBC 分组差异](../02_测试结果/第5关_CBC篡改实验/03_CBC篡改对比.png)

“随机生成 IV”会给出新的16位值，可用于其他实验，解密必须保留加密时的IV。解密所需参数是密钥、IV和密文；原明文和历史记录只用于界面差分比较。若更改密钥或IV并重新解密，旧比较基准将不再显示。
修改字段后，当前版本会撤下旧结果并提示重新计算。已归档的截图来自改进前版本，输入、密钥和运算结果仍可按各关记录复现。

## 8. 排错与结束

| 现象 | 建议处理 |
|---|---|
| 找不到 Python 或窗口未打开 | 使用本机Anaconda或带Tkinter的Python；从终端启动查看错误 |
| 找不到 main.py 或 saes.py | 保留01_源代码目录中的文件，在项目根目录使用启动脚本 |
| 提示位数不正确 | 核对是16、32还是48位，保留前导零 |
| HEX 格式不正确 | 使用完整十六进制字节，不要粘贴二进制或字符映射 |
| 提示 ASCII 或填充无效 | 核对是否输入中文、密钥是否一致、密文是否完整 |
| 显示“原结果已失效” | 输入或模式已改变，重新点击对应操作按钮 |
| 修改IV后提示重算 | 当前程序已撤下旧结果，点击加密或解密重新计算 |
| MITM 候选过多 | 增加同密钥下的独立明密文对，而不是仅重复同一对 |

关闭窗口即可退出；正在运行的攻击会收到取消信号。提交前保存所需数据，图形界面不会自动归档每次操作。
