# GitHub上传教程：从本地作业到提交仓库链接

本教程对应当前的S-AES作业目录，采用浏览器网页上传方式。无需先学习Git命令，也不需要把Python文件合并。

## 第一步：准备上传内容

本地项目位于 `D:\信息安全导论\S-AES作业`。根目录应包含以下内容：

```text
01_源代码/
02_测试结果/
03_相关文档/
.gitignore
README.md
启动程序.bat
运行测试.bat
```

我已另备好 `D:\信息安全导论\S-AES作业_GitHub上传包.zip`，里面是移除Python缓存后的项目副本。建议将它解压到一个新位置，打开其中的“S-AES作业”文件夹，再按本教程上传里面的内容。

上传的是解压出来的文件和目录，不是把ZIP作为唯一文件上传。否则老师需要先下载解压，无法直接在仓库阅读文档和截图。

若直接使用原项目，检查 `01_源代码` 及其 `tests` 目录：`__pycache__`、`.pyc`文件均不需要上传。网页上传时，不要把.gitignore当作替你筛掉已选择文件的工具；它主要用于Git提交工作流。干净上传包已排除这些缓存。

本次第一、三、四、五关已有运行证据；第二关的真实组间测试仍待补充。可先上传，完成后再更新对应文件；最终课程提交前补齐实际记录。

## 第二步：登录并创建仓库

1. 打开 [GitHub](https://github.com)，登录自己的账号。
2. 点击右上角“+”，选择“New repository”；也可直接打开 [新建仓库页面](https://github.com/new)。
3. Owner选择自己的账号，Repository name可填 `saes-coursework`。
4. Description可填：`信息安全导论课程作业：S-AES加解密、密钥恢复与CBC实验`。
5. 按课程访问要求选择可见性。选择Public时，老师可直接用链接访问；选择Private时，需另行确保老师获得权限。
6. 关闭“Add a README file”，.gitignore选择None，许可证先保持None。本项目已自带README和.gitignore，不必让网站重复生成。
7. 点击“Create repository”。

本步骤是新建你自己的仓库，不需要Fork参考仓库。项目README已保留文档组织参考的说明。

## 第三步：进入上传页面

新建的空仓库中，找到“uploading an existing file”并点击。
如果仓库已经有文件，点击“Add file → Upload files”。

页面出现上传区域后，将浏览器和资源管理器并排摆放，方便拖入文件。

## 第四步：拖入正确层级

在资源管理器中进入解压后的“S-AES作业”文件夹，确认已经能看见01、02、03三个目录和README。

选择这三个目录、README.md、两个.bat和.gitignore，将它们一起拖入网页上传区域。尽量使用拖放保留目录，而非进入各子目录后逐个选择文件。

**不要把外层“S-AES作业”文件夹整体拖入。** 仓库首页应直接出现01、02、03和README，而不是只有一层“S-AES作业”目录。

等待文件列表加载完毕，核对路径示例：

```text
README.md
01_源代码/main.py
01_源代码/saes.py
01_源代码/experiment_io.py
02_测试结果/五关测试结果.md
02_测试结果/第1关_基础加解密/01_基础加密.png
03_相关文档/用户指南.md
```

如果所有图片都出现在仓库顶层，或文件只剩文件名而没有预期子目录，先取消本次选择，回到正确的项目根目录重新拖放。

浏览器一次最多上传100个文件，单文件上限25MiB。本项目当前的干净上传包在这一范围内。以后如果添加大量新截图导致超限，可分批上传，保持相同相对目录。

## 第五步：提交文件

1. 上传列表完整后，在下方提交信息中填写：`提交S-AES源码、五关实验记录和使用文档`。
2. 对于新建且由你维护的课程仓库，可选择直接提交到main分支。
3. 点击“Commit changes”；若弹出确认对话框，再确认一次。按钮可能先显示为“Commit changes...”。
4. 等页面跳转回仓库文件列表。

只有文件已经出现在仓库列表中，才代表这次上传提交完成。不要仅停留在上传区域就关闭页面。

## 第六步：检查网页展示

依次做以下检查：

| 检查位置 | 应看到的内容 |
|---|---|
| 仓库首页 | 01_源代码、02_测试结果、03_相关文档、README和启动脚本 |
| 首页文件列表下方 | 排版后的README，有项目介绍和功能导航 |
| 点击README里的“五关实验总览” | 打开五关测试结果.md |
| 点击第一关实验记录 | 有输入输出表、分析和两张原始截图 |
| 点击第四、五关记录 | 能看到密钥恢复、CBC正常与篡改对比 |
| 点击用户指南、开发手册和接口文档 | 可直接阅读排版后的Markdown |
| 打开01_源代码 | main.py、saes.py、experiment_io.py、verify.py等都在 |

不需要把.md转PDF。若打开后只有Markdown源代码，可选择文件顶部的“Preview”预览；README默认在仓库首页展示。
图片不显示时，先核对图片是否上传，再核对文件夹名、大小写、文件名是否与文档链接完全一致。

## 第七步：复制仓库首页链接并提交

回到仓库“Code”首页，复制浏览器地址。形式为 `https://github.com/你的用户名/saes-coursework`；这是格式示例，使用你实际创建仓库的地址。

提交给老师的是仓库首页链接，不是单张图片地址、本地D盘路径或参考仓库地址。浏览器地址通常不必带.git后缀。

按老师要求打开石墨提交表格，在本组行填写成员和仓库地址，确认保存。课程入口见 [提交说明](提交说明.md)，实际以课程群发布的原始链接为准。

## 第八步：以后如何补交或更新

若尚未首次上传，使用干净上传包即可。若后续又修改了本地项目，上传包不会自动跟着变化，应使用修改后的文件，或重新整理上传副本。

- 改一个Markdown文件：进入仓库相应文件，点击铅笔编辑，修改后提交；也可以上传本地新版到相同路径。
- 更新整个关卡：从仓库根目录进入“Add file → Upload files”，拖入本地的“02_测试结果”目录，保持完整路径；提交前核对待更新文件列表。
- 补第二关：上传对方运行截图、填写后的组间记录，以及更新后的第二关实验记录和五关总览。
- 改文件名或目录：同时修改引用它的Markdown链接，避免断图。

网页更改与本地文件不会自动同步。尽量确定一份最新内容，避免下次用旧上传包覆盖新的组间测试记录。
