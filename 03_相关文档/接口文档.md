# 5.2.3 相关文档：算法模块接口

## 使用方式

模块位置为 `01_源代码/saes.py`，可独立于界面使用。在 `01_源代码` 中创建脚本或打开 Python，再执行 `import saes`。要求 Python 3.10+，无需第三方依赖。

所有单分组与子密钥均为 0…65535 的整数；多重加密密钥为含 2 或 3 个整数的序列。完整算法约定见 [开发手册](开发手册.md)。

## 基础接口

| 函数 | 输入 | 返回／错误 |
|---|---|---|
| `parse_bits(text, length=16)` | 二进制文本及位数，允许空白 | 整数；无效格式抛出 ValueError |
| `expand_key(key)` | 16 位密钥 | `(K0,K1,K2)` |
| `encrypt(block,key)` / `decrypt(block,key)` | 16 位分组、密钥 | 16 位整数 |
| `encryption_trace(block,key)` / `decryption_trace(block,key)` | 明文或密文、密钥 | 正向或逆向的 `(步骤名,状态整数)` 列表 |

```python
import saes
assert saes.encrypt(0xD728, 0x4AF5) == 0x24EC
assert saes.decrypt(0x24EC, 0x4AF5) == 0xD728
assert saes.expand_key(0x4AF5) == (0x4AF5, 0xDD28, 0x87AF)
```

## 多重加密

| 函数 | 输入 | 返回 |
|---|---|---|
| `double_encrypt(block,keys)` | block、`(K1,K2)` | `E_K2(E_K1(block))` |
| `double_decrypt(block,keys)` | block、`(K1,K2)` | `D_K1(D_K2(block))` |
| `triple_encrypt(block,keys)` | block、2 或 3 个子密钥 | EEE 密文，2 个子密钥时第三次复用 K1 |
| `triple_decrypt(block,keys)` | 密文、同一组子密钥 | 逆序解密所得明文 |

```python
keys = (0x4AF5, 0xDD28)
cipher = saes.double_encrypt(0xD728, keys)
assert saes.double_decrypt(cipher, keys) == 0xD728
keys3 = (0x4AF5, 0xDD28, 0x1234)
cipher3 = saes.triple_encrypt(0xD728, keys3)
assert saes.triple_decrypt(cipher3, keys3) == 0xD728
```

## ASCII 与字节分组

| 函数 | 输入 | 返回 |
|---|---|---|
| `encrypt_ascii(text,key)` | ASCII 字符串、密钥 | 填充加密后的 bytes |
| `decrypt_ascii(data,key)` | 非空密文 bytes、密钥 | 去填充后的 ASCII str |
| `bytes_to_blocks(data)` | 偶数字节的 bytes | 大端序 16 位分组列表 |
| `blocks_to_bytes(blocks)` | 16 位整数序列 | 大端序 bytes |
| `pad(data)` / `unpad(data)` | bytes | 添加／检查移除 2 字节 PKCS#7 填充 |

```python
cipher = saes.encrypt_ascii("Hello S-AES!", 0x4AF5)
hex_cipher = cipher.hex().upper()
assert saes.decrypt_ascii(bytes.fromhex(hex_cipher), 0x4AF5) == "Hello S-AES!"
```

非 ASCII 输入、奇数字节密文、空密文、无效填充和不能解码的结果会抛出 ValueError。密文使用 HEX 无损传输，调用解密接口前先使用 `bytes.fromhex()`。

## CBC

| 函数 | 输入 | 返回 |
|---|---|---|
| `random_iv()` | 无 | secrets 生成的随机 16 位 IV |
| `cbc_encrypt(blocks,key,iv)` | 明文分组、16 位密钥和 IV | 密文分组列表 |
| `cbc_decrypt(blocks,key,iv)` | 密文分组、原密钥和 IV | 明文分组列表 |

CBC 接口不填充，调用方负责提供完整分组，保存并共享 IV。

```python
plain = [0x1234, 0x5678, 0x9ABC]
iv = saes.random_iv()
cipher = saes.cbc_encrypt(plain, 0x4AF5, iv)
assert saes.cbc_decrypt(cipher, 0x4AF5, iv) == plain
cipher[0] ^= 1
changed = saes.cbc_decrypt(cipher, 0x4AF5, iv)
assert changed[1] == plain[1] ^ 1
assert changed[2] == plain[2]
```

## 中间相遇攻击

`meet_in_middle(pairs, progress=None, cancelled=None)`：

- `pairs`：非空 `(明文整数,双重加密密文整数)` 序列。
- `progress`：可选回调，接收 `(已扫描数,131072)`；进度不包含候选过滤工作量。
- `cancelled`：可选无参回调；返回 True 时抛出 InterruptedError。
- 返回全部满足输入明密文对的 `(K1,K2)` 列表，可能为空或包含多个候选。

```python
keys = (0x4AF5, 0xDD28)
pairs = [(p, saes.double_encrypt(p, keys)) for p in (0xD728, 0x1234, 0xABCD)]
candidates = saes.meet_in_middle(pairs)
assert keys in candidates
```

搜索完整的 16 位 K1/K2 空间，保留所有中间值碰撞。建议至少提供三对独立明密文进行过滤。图形界面通过后台线程调用接口。


## 文件交换契约

“交叉测试”页使用UTF-8 JSON。algorithm必须为S-AES，key为16位二进制字符串，vectors为非空数组，每项含plaintext和ciphertext。格式如下：

```json
{
  "algorithm": "S-AES",
  "key": "0100101011110101",
  "vectors": [
    {
      "plaintext": "1101011100101000",
      "ciphertext": "0010010011101100"
    }
  ]
}
```

交叉测试页导出的密钥来自当前输入框；导入使用JSON内的key，并将该值回填到界面密钥框，输出也标明文件路径和文件密钥。
验证同时检查encrypt(P,K)=C和decrypt(C,K)=P。文件正确不代表已取得其他小组运行证据，组间状态应由双方实际记录确定。

中间相遇页的“导出全部候选”保存JSON数组，每项为二进制字符串K1、K2，例如：

```json
[
  {"K1": "0100101011110101", "K2": "1101110100101000"}
]
```

界面最多显示100对，但导出包含全部候选。原始完整截图的来源与校验值记录在 [截图清单](../02_测试结果/截图清单.json)。

## 实验数据模块 experiment_io

本模块不依赖GUI，负责文件内容与攻击输入的严格校验：

| 接口 | 返回值／行为 |
|---|---|
| `make_vectors(key)` | 包含algorithm、key、四项vectors的字典 |
| `verify_vectors(text)` | `(key, list[VectorResult])`；格式不合法时抛ValueError |
| `parse_attack_pairs(text)` | 明密文整数对列表；错误带实际行号 |

VectorResult为只读数据类，含plaintext、ciphertext、actual_ciphertext、recovered_plaintext；passed属性检查双向一致性。算法结果不一致会返回passed=False，并可显示实际值；文件结构错误则抛ValueError，避免将部分读取结果误记为通过。
JSON只接受algorithm=S-AES、字符串密钥、非空数组vectors及每项合法二进制字段；支持UTF-8 BOM。公共二进制、字节及密钥接口现在先验证类型，非法类型统一给出ValueError；密钥缓存置于校验之后。
